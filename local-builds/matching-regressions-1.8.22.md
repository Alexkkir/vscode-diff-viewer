# Регрессии матчинга из диалога — 1.8.22

Добавлено 11 составных синтетических историй: перевод аргументов вместе с новыми ключами и переименованными элементами списка; удаление комментариев вместе с распрямлением импортов; условия и ранние возвраты; переименование декорированного класса с переносом URL; сохранение конструктора среди удаляемых копий; несвязанные строки, которые должны остаться отдельными добавлениями/удалениями.

Для каждой истории проверены оригинал, обратное направление, добавленный начальный контекст с разными смещениями номеров и сочетание этих вариантов. Ещё два теста сохраняют исходный текст патча для проверки границы контекста и пропущенного диапазона между hunks. Всего 46 сценариев, каждый в двух раскладках и трёх режимах matching.

## Что именно проверяется

Ожидания пар, добавлений и удалений заданы вручную в `src/shared/testing/conversation-matching-corpus.ts`, независимо от алгоритма. Parser → hunk realignment → renderer должны сохранить точный текст, номера и порядок обеих сторон; повторное выравнивание не меняет модель. `lines` и `words` дополнительно обязаны сохранить заданные визуальные пары. Для `none` проверяется сохранность исходников: этот режим сохраняет позиционное сопоставление.

В единой колонке соседства недостаточно: заменённые строки должны быть непосредственно соседними и обе иметь маркер парной замены. Контекстная пара должна быть одной строкой с обоими номерами. В двух колонках у отдельного добавления/удаления противоположная ячейка не содержит ни номера, ни текста. Общий прежний contract runner также усилен проверками противоположной ячейки.

## Ошибки, обнаруженные тестами

До исправления падали шесть вариантов двух историй. Ожидания не ослаблялись; нет skipped/failing тестов вместо исправления.

1. **Класс и перенесённый комментарий.** Сходство длинного URL перетягивало пару на соседний удаляемый класс. При конкуренции объявлений на обеих сторонах комментарий, перенесённый в обычный текст, теперь имеет меньший вес. Распознанные простые формы комментирования исполняемого кода и случаи без конкурирующих объявлений сохраняют прежние веса; Markdown и текстовые пути покрыты отдельными проверками.
2. **Конструктор в обратном diff.** При равной оценке удалённая документация или пустая строка заставляли пропускать первую новую копию тела. Сохранение старой строки теперь требует доступного совпадения впереди. Если перепривязка тела увеличивает только whitespace edits, она допускается лишь при точном сохранении набора и количества всех смысловых контекстных строк. Отдельные тесты запрещают превращать маленький перенос в сотни изменений пустых строк.

Вес комментариев остаётся эвристикой, не полноценным синтаксическим анализом: typed/indexed assignments не входят в узкий распознаватель целей. При неоднозначных перестановках рядом с объявлениями этот случай требует отдельного будущего примера с однозначным ожидаемым сопоставлением.

## Результаты и запуск

- `npm run test:matching`: 448 тестов, 8 suites.
- `npm test -- --runInBand`: 1044 теста, 48 suites.
- `npm run test:coverage:ci -- --runInBand` проходит: line-alignment.ts — 99.63% строк / 97.72% ветвей; hunk-alignment.ts — 98.78% строк / 94.33% ветвей.
- TypeScript, ESLint, форматирование и production build проходят.
- `node integration/browser/line-alignment.cjs`: 76 сценариев, ноль browser errors; проверены геометрия, пары и исходные проекции. Browser harness использует тот же новый corpus.
- Независимые взаимные ревью обеих правок завершены без блокирующих замечаний.

Инструкция по расширению набора находится в `CONTRIBUTING.md`, раздел Diff Matching Regressions. Все примеры публичные синтетические; полные приватные исходники не копировались. Краткий browser-отчёт, проверенный скриншот и хеши итоговой сборки находятся в `matching-regressions-1.8.22/`.
