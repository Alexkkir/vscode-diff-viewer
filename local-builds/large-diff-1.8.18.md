# Большие diff и актуальность превью — 1.8.18

Проверены два присланных файла: 20 459 строк / 313 файлов и 6 657 строк / 73 файла. В репозиторий сохранены только числовые результаты, исходники тестов и способы повторения. Приватные тексты, имена файлов, screenshots и traces не публикуются.

## Изменения

- Для больших diff создаются заголовки; свёрнутые тела отсутствуют в DOM. Нет предварительной подсветки всего закрытого diff и ожидания чтения всех исходников.
- Тело и native syntax запрашиваются при раскрытии файла. Лексическая и семантическая подсветка приходят отдельными обновлениями с исходными индексами файлов.
- Expand all раскрывает по файлам с уступкой браузеру. Измерение общей полосы прокрутки порционное, результаты кешируются; положение восстановленной прокрутки учитывается в кеше.
- `content-visibility` применяется к телам файлов, сохраняя sticky-заголовки. Диагональный фон больше не привязан к viewport, уменьшая перерисовку при прокрутке.
- При изменении файла старое превью скрывается и появляется **Updating diff…** до готовности нового. Это относится и к короткому пустому состоянию при `> diff.diff`. Фокус без изменения файла не скрывает превью.
- Устаревшие render/syntax результаты отменяются. Запросы чтения source прекращаются между `stat/read`. Файлы без расширения не прерывают подсветку остальных файлов.

## Полный запуск в установленном VS Code

Отдельный профиль, локальная файловая система, одинаковые настройки: список файлов включён, общая прокрутка включена, matching `none`. В baseline использован сохранённый VSIX 1.8.17. Это не эмуляция скорости удалённого dev-сервера.

| 20k, line-by-line                          |  1.8.17 |                 1.8.18 |
| ------------------------------------------ | ------: | ---------------------: |
| Open command → показ свёрнутого preview    | 1625 мс |                 421 мс |
| Строк кода в DOM до раскрытия              |  19 189 |                      0 |
| Старый preview через ~80 мс после truncate |   виден | скрыт, Loading включён |

В 1.8.18 side-by-side collapsed показан за 436 мс; первое тело — за 145 мс, native цвета — за 157 мс. В line-by-line первое тело — 199 мс, native цвета — 206 мс. Повторный focus оставил preview видимым без Loading.

## Browser-only сравнение

Тот же webview bundle и CSS в headless Chromium; исключены extension host, filesystem/source lookup и native language providers. Это полезно для сравнения DOM/layout/paint, но не является замером полной пользовательской задержки.

| Метрика                                         |     До, LBL / SBS | После, LBL / SBS |
| ----------------------------------------------- | ----------------: | ---------------: |
| 20k collapsed                                   |      519 / 604 мс |       92 / 84 мс |
| DOM elements до раскрытия                       | 192 902 / 285 185 |    4 733 / 6 298 |
| Полное Expand all                               |    1181 / 1983 мс |   2004 / 3617 мс |
| Максимальный перерыв кадров во время Expand all |     991 / 1783 мс |      43 / 108 мс |
| Промежуточные кадры раскрытия                   |             0 / 0 |         98 / 115 |
| 6k scroll p95 интервала кадров                  |    17,5 / 34,2 мс |     17,5 / 25 мс |

Полное Expand all занимает больше общего времени, потому что браузеру возвращается управление и измерения распределены между кадрами. Оно перестало быть одной длительной блокирующей операцией. Одиночный большой файл всё ещё может потребовать заметного времени при раскрытии.

В установленном VS Code прокрутка 6k вскоре после открытия дала p95 17,4 / 16,7 мс; отдельные паузы достигали 58 / 133 мс при поздней подсветке или первом layout тел. Это улучшение типичной прокрутки, а не обещание отсутствия любых задержек. Скрытие после invalidate полностью раскрытого 20k в browser-only SBS заняло 214 мс, включая сохранение позиции.

## Проверки и повторение

900 unit-тестов, TypeScript, ESLint и форматирование проходят. Пройдены все 28 групп реального UI и восемь desktop-регрессий. Large-diff harness проверяет пустой DOM кода у collapsed-файлов, отсутствие ранних syntax requests, завершение реальных scrollbar measurements, скрытие stale preview, unchanged focus и отрисовку обоих предоставленных файлов.

```sh
npm ci
npm test -- --runInBand
npm run build:prod
DIFF_BENCH_EXPECT_LAZY=1 node integration/browser/large-diff.cjs /tmp/large-browser
node scripts/test-large-diff-desktop.mjs
```

Нужны Node.js 22 и Playwright/Chromium; desktop runner использует установленный VS Code в отдельном временном профиле. `VSCODE_EXECUTABLE` задаёт executable. По умолчанию данные синтетические; `DIFF_BENCH_FIXTURE` и `DIFF_BENCH_SCROLL_FIXTURE` задают внешние 20k/6k файлы. `DIFF_BENCH_ASSETS` выбирает сохранённый browser bundle; `DIFF_LARGE_EXTENSION_PATH` — извлечённый baseline VSIX. `DIFF_LARGE_BASELINE=1` записывает старое поведение без требований новой версии.

Числовые отчёты находятся в `large-diff-1.8.18/`; полный UI-отчёт — в `ui-controls-1.8.18/report.json`. Хеши bundle сверяются с итоговым VSIX.
